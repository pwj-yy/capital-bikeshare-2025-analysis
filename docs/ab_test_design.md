# Casual 用户定向优惠 A/B Test 方案

## 1. 实验定位

本方案用于检验定向优惠能否恢复符合条件的 casual 用户骑行需求，是定价政策历史分析之后的后续实验建议，**尚未执行**。公开 Capital Bikeshare trip history 不含 `user_id`、实验分组或曝光信息，因此无法用现有公开数据完成随机化、曝光核验或实验效果估计。

## 2. 实验设计

- **目标人群：** 满足预先定义资格条件、近期有使用或回流可能的 casual 账户；资格规则须在随机化前冻结。
- **Treatment：** 向账户发放一次明确有效期和使用条件的骑行优惠券。
- **Control：** 维持当前价格，不发放优惠。
- **随机化单位：** `user/account`，同一账户只能进入一个组，避免跨骑行污染。
- **分析原则：** 以分配结果为准做 ITT（intention-to-treat）分析；无论用户是否打开或使用优惠券，都保留在原分组中。
- **观察窗口：** 从分配时点起 7 天；两组应同期运行，并对同一账户只设置一个起始时点。

在上线前应排除员工/测试账户，检查一个账户对应多个营销渠道等污染风险，并确保控制组不会通过其他活动获得同类优惠。

## 3. 指标与假设

**主要指标**

```text
7 日内是否完成至少一次骑行（binary）
```

主要效应为两组 7 日骑行转化率之差：

```text
H0: p_treatment - p_control = 0
H1: p_treatment - p_control != 0
```

采用双侧检验，`alpha = 0.05`、`power = 0.80`。主要指标只设一个主检验，避免从多个指标中挑选显著结果。

**次要指标**

- 7 日 rides per user；
- 观察期内 membership conversion；
- classic/electric bike-type mix。

**护栏指标**

- revenue per user；
- promotion cost per incremental rider / ride；
- 对原本会按原价骑行用户的 cannibalization；
- 退款、投诉或异常账户比例（如业务系统可用）。

次要与护栏指标用于解释商业价值和风险，不替代主要指标的预注册判断。

## 4. MDE 与示例样本量

假设控制组 7 日至少一次骑行率为 20%，希望识别提升至 22%，即绝对 MDE 为 2 个百分点（相对提升 10%）。在等比例分组、双侧 `alpha = 0.05`、`power = 0.80` 下，正态近似的两独立比例检验约需 **6,508 个账户/组，合计约 13,016 个账户**。

仓库脚本已提供可复用函数：

```python
from analysis.pricing_policy_analysis import sample_size_per_arm

n_per_arm = sample_size_per_arm(
    baseline_rate=0.20,
    mde=0.02,
    alpha=0.05,
    power=0.80,
)
print(n_per_arm)  # 约 6508
```

该数字仅为设计示例，不是现有数据估计出的最终招募量。正式上线前应使用账户级历史基线率重算；若存在真实的结果数据缺失，可按预期损耗预留样本。优惠券未送达或未使用属于 ITT 效应的稀释，应体现在更保守的预期提升/MDE 中，不能简单删除这些账户或仅用损耗系数代替。不应在实验中途根据显著性反复调整样本量。

## 5. 执行与决策规则

1. 在实验开始前冻结资格、主指标、窗口、样本量与分析代码；
2. 完成账户级随机化后检查组间样本量及关键历史特征是否存在明显实现错误；
3. 按 ITT 报告转化率差、95% 置信区间和 p 值，同时报告次要及护栏指标；
4. 只有当主要指标改善、商业收益能够覆盖促销成本且护栏无不可接受恶化时，才建议扩大投放；
5. 若结果不显著或收益不足，如实保留结果，不把优惠券使用者的自选择表现解释为实验效果。
