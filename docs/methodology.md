# 分析方法与口径

## 1. 研究问题

2025 年 Capital Bikeshare 骑行需求在时间、用户类型、站点和 OD 线路上呈现什么规律？这些规律能为高峰保障、补车和清桩提供哪些方向性线索？

本项目采用描述性统计和探索性可视化，不建立需求预测模型，也不把相关性解释为因果关系。

## 2. 数据范围

- 官方 2025 年 1-12 月 trip history，共 12 个文件、6,662,647 条记录。
- 以 `started_at` 判断研究年份：保留在 2025 年开始的骑行。
- 12 个文件均包含相同的 13 个原始字段，名称、数量和顺序一致。

## 3. 清洗规则

脚本按 250,000 行分块读取，避免一次性把约 1.3 GB CSV 全部载入内存。每条记录按下列顺序检查：

1. `ride_id` 后续重复记录；
2. 无法解析的开始或结束时间；
3. `started_at` 不在 2025 年；
4. `duration_min <= 0`；
5. `duration_min > 1,440`（24 小时）。

本次完整重跑没有重复 ID 或无法解析时间，实际删除：

| 原因 | 删除行数 |
| --- | ---: |
| `started_at_outside_2025` | 36 |
| `duration_non_positive` | 35 |
| `duration_over_24h` | 4,673 |
| 合计 | 4,744 |

清洗后保留 6,657,903 条，保留率 99.93%。官方数据页说明 trip history 已进行过工作人员/测试站与疑似误操作短骑行处理，因此本项目不再次机械删除所有 1 分钟以下记录。

## 4. 派生字段

- 时间：`duration_min`、`date`、`month`、`weekday`、`hour`、`is_weekend`。
- 站点：优先使用 station ID，缺失时回退到站点名称形成分析键。
- OD：优先拼接起终点 station ID；ID 不完整时回退到起终点站名。
- 同站还车：优先比较起终点 station ID；ID 不完整时比较标准化站名。

## 5. 三个分析分母

### 5.1 清洗后主表：6,657,903 条

用于总体、月份、星期、小时和 member/casual 分析。

### 5.2 任一端站点有效的记录

热门站点使用量分别统计所有有效起点 departures 和所有有效终点 arrivals，再按站点相加。因此，一端站点缺失不会导致另一端的有效使用信息被丢弃。

### 5.3 完整 station/OD 子集：4,541,427 条

要求起终点 station ID 均完整，或起终点站名均完整。用于：

- departures - arrivals 年度差值；
- OD 组合计数与排序；
- 同站还车和 OD 时长结构。

站点平衡必须使用这一完整子集；否则单端站点缺失会人为制造 departures 或 arrivals 差异。

## 6. 指标定义

### 周末强度指数

```text
周末强度指数 = 周末骑行数 / 104 天 ÷ (工作日骑行数 / 261 天)
```

2025 年有 261 个周一至周五、104 个周六/周日。该指标避免直接比较全年工作日和周末总量造成的天数偏差。

### 站点使用量

```text
total_usage = departures + arrivals
```

### 站点方向性差值

```text
balance_gap = departures - arrivals
```

- 正值：全年出发更多，可作为潜在缺车/补车监测候选。
- 负值：全年到达更多，可作为潜在满桩/清桩监测候选。

该指标是年度方向性线索，不是实时库存或调度绩效指标。

## 7. 复现核验

公开版 `src/prepare_data.py` 已使用本地 12 个原始文件完整重跑，并复现以下核心结果：

| 指标 | 重跑结果 |
| --- | ---: |
| 原始行数 | 6,662,647 |
| 清洗后行数 | 6,657,903 |
| 删除行数 | 4,744 |
| station/OD 子集 | 4,541,427 |
| 分析站点键 | 1,108 |

| 重复 `ride_id` | 0 |

## 8. 解释边界

- 不使用“member 一定是通勤、casual 一定是旅游”的确定性表述，只根据时段、日型和时长给出更可能的场景解释。
- 不把 OD 直线当作真实骑行轨迹。
- 不把年度站点差值当作实时缺车或满桩证明。
- 不把站点/OD 子集结论外推为全部骑行记录的无偏空间分布。
- 保留的交互地图使用既有坐标绘图层（1,118 个节点）；主站点分析使用优先 ID、缺失回退名称的 1,108 个站点键。两者构造规则不同，地图节点数不作为站点总数口径。
